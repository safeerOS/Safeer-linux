# Safeer Browser for Linux 1.0.91 · Safeer Control 2.1.47 · Safeer OS 0.4.49

## Safeer Control 2.1.47

- **Safeer Link connections on the computer no longer break under load.** When a lot of data went both ways over one Link connection, the computer could decide that the other side had closed it. The connection was dropped and built again, whatever was on its way was lost, and until the direct connection came back messages took a detour through another device. The network was never the cause. On the same encrypted connection one thread reads and another writes, and inside the TLS library a write could wipe the "nothing yet, try again" state of a read, which Python then reported as the end of the connection. Every Link connection on the computer — the hub's and the ones to other hubs — now goes through one guarded wrapper (`core/link_vticnik.py`). Link sockets are also opened with `TCP_NODELAY`, and when a connection ends for any reason other than the other side closing it, the log says why.
- **New: internet through a phone.** A phone with Safeer OS Mobile 0.5.47 can lend its internet connection to this computer over Safeer Link. It is not a hotspot: the phone stays on Wi-Fi with the computer, and what the computer sends leaves through the phone's mobile network. Three modes: off (the default), only while the home connection is down, always. Safeer Control runs a local proxy (`127.0.0.1:47890`; SOCKS5, SOCKS4a, HTTP `CONNECT`, HTTP) and, unless you turn that off, sets the desktop's proxy only while traffic really goes through the phone and afterwards puts back exactly what was there — also after a crash. Destinations in the home network (printer, router, `name.local`) always go directly. On the phone, sharing has to be switched on and this computer allowed; mobile data, roaming and a monthly limit are separate switches there. Another user of the same computer cannot use the proxy.
- **Large transfers hold.** The first version of the phone side (Safeer OS up to 0.5.46) had no flow control: a download faster than Link could carry filled the hub's queue and took the phone's whole Link connection down. Protocol 2 bounds what is on its way (256 KiB per device, 128 KiB per connection), numbers every chunk so that a lost one ends the connection instead of corrupting it, and recovers by itself when either side restarts. See [docs/INTERNET-GATEWAY.md](docs/INTERNET-GATEWAY.md).
- **`safeerctl internet`** — status, `mode off|failover|always`, `test` (one real request through the phone: which network it took and with which public address), `env` (proxy variables for a shell). See [docs/SAFEERCTL.md](docs/SAFEERCTL.md).

## Safeer OS 0.4.49

- **Network connections › Internet through the phone.** Choose the mode, see which phones in Safeer Link share their internet and whether this computer is allowed, what is in use right now and how much went through the phone today and this month, and run a test that shows which network the request really took. While the phone is still waiting for your decision, Safeer OS says what to do on the phone.

Measured on real devices. Through the mobile network of a current flagship phone lying with its screen off: 11 MB/s for one connection (50 MB over TLS), 17 MB/s for eight in parallel, 1.3 MB/s upload (the uplink of the mobile network); the phone stayed on Wi-Fi and brought the mobile network up for the request in under half a second. Through a mid-range phone (its Wi-Fi path): 5.6 MB/s for one connection, 7 MB/s for four, 5 MB/s upload. Every file arrived identical byte for byte; four and eight parallel downloads, 50 MB over TLS and a 20 MB upload went through without a break, and restarting Safeer Control or the phone app in the middle of four downloads recovers within seconds.

Not yet: UDP (and with it QUIC/HTTP3 — browsers fall back to TCP). Programs that ignore proxy settings (for a terminal: `eval "$(safeerctl internet env)"`). Chromium-based browsers follow the desktop's proxy on GNOME, Cinnamon and similar desktops, not on Xfce, LXQt or KDE — set the proxy there by hand. A connection that loses a chunk ends and the program retries; resuming and a direct data connection between the two devices are next. Switching to the phone when the home connection really fails is covered by tests, but has not yet been tried on a live outage.

Safeer Browser 1.0.91 has no changes of its own (same code, new number).
