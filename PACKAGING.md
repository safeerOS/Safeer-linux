# Linux distribution

Since 14 Oct 2026 Safeer Browser for Linux is `safeer_brskalnik.py`: Python, PyGObject, GTK 4, WebKitGTK 6.0 (not Chromium), Soup 3 and GStreamer; the browser view is Splet (`core/os_splet.py`), the same code as the web browser in Safeer OS. All formats install the same application via `packaging/install_payload.sh`; launchers resolve their payload relative to themselves.

Which WebKitGTK each format runs:

| Format | WebKitGTK | Distributions |
|---|---|---|
| Flatpak | **ours**, with the patches in `packaging/webkit` (same module file as Safeer OS) | any with Flatpak and GNOME 50 runtime |
| .deb (amd64) | ours, the same WebKitGTK 2.54 and libsoup 3.8 as the Flatpak (same sources, patches and options, Clang 22 ThinLTO), built for Ubuntu 24.04 by `packaging/webkit-deb` into the shared package `safeer-webkit` (private prefix `/usr/lib/safeer-webkit`, required by `safeer-browser` and `safeer-os`); the system's WebKitGTK is neither needed nor touched. If the Safeer Browser Flatpak is installed and not older, the .deb launcher starts the Flatpak instead (`SAFEER_BRSKALNIK_BREZ_FLATPAKA=1` keeps the .deb) | Linux Mint 22+, Ubuntu 24.04+ |
| AppImage | the build host's (Ubuntu 24.04) libraries, bundled | glibc 2.39+ |

The GTK 3 browser (`safeer_mint.py`, WebKit2GTK 4.1) was retired on 18 Oct 2026; every package is GTK 4 with WebKitGTK 6.0.

## Debian / Ubuntu / Mint

Install build dependencies: Python 3, Pillow, dpkg-dev, desktop-file-utils and appstream. Runtime dependencies are recorded in the Debian control file generated by `build_deb.sh` (GTK 4, `safeer-webkit (>= <release>)` and the GStreamer codecs in `Depends`, because GDebi does not install recommended packages); `safeer-webkit` itself depends on the libraries of our WebKitGTK (`dpkg-shlibdeps`), bubblewrap and xdg-dbus-proxy for its sandbox and glib-networking for TLS.

```sh
sudo bash packaging/webkit-deb/odvisnosti.sh                     # Clang 22 (apt.llvm.org, key fingerprint and package version pinned) and the noble -dev packages
sudo bash packaging/webkit-deb/zgradi.sh /usr/lib/safeer-webkit build/safeer-webkit.tar.zst   # 2-3 h, in a clean container (refuses a prefix an installed package owns)
SAFEER_DAV1D=build/dav1d bash packaging/webkit-deb/paket.sh build/safeer-webkit.tar.zst   # safeer-webkit_1.0.127_amd64.deb
SAFEER_WEBKIT_DEB=safeer-webkit_1.0.127_amd64.deb bash build_deb.sh
sudo apt install ./safeer-webkit_1.0.127_amd64.deb ./safeer-browser_1.0.127_amd64.deb   # both in one command (GDebi: safeer-webkit first)
```

Our WebKitGTK and libsoup are built from the Flatpak modules themselves (`packaging/webkit-deb/modul.py` reads the archive, SHA-256, patches and CMake/meson options of `packaging/webkit/webkitgtk6-safeer.yml` and `packaging/libsoup/libsoup3-safeer.yml`), so the two formats cannot drift apart. They are installed into one private prefix, `/usr/lib/safeer-webkit`, shipped once by the package `safeer-webkit` (`packaging/webkit-deb/paket.sh`; WebKit compiles the path of its helper processes into the library, so the prefix is fixed). Until 1.0.127~pred every package carried its own copy (`/usr/lib/<package>/webkit`, ~135 MB each, different files because of the prefix): with Safeer OS and Safeer Browser running, the kernel held the engine's code twice (measured on the test PC 18 Oct 2026: ~60-70 MiB libwebkitgtk + ~30 MiB JavaScriptCore) and CI built WebKit twice. `safeer-os` and `safeer-browser` depend on `safeer-webkit (>=` the release`)`: a lower bound, so updating one program never removes the other (the WebKitGTK 6.0 API and soname are stable); the package version is the release (`packaging/VERSION`). On an upgrade from a package with its own copy, dpkg removes the old `/usr/lib/<package>/webkit` files itself (they are not in the new package); `tools/mint_namestitev` checks that nothing is left. The in-app update of Safeer OS installs `safeer-webkit` in the same `apt-get` as the program (`webkit_deb` in the signed version list; for 1.0.126 clients the stable list also carries it as `tema_deb`, which they already install the same way). The libraries find each other through `DT_RPATH`, the typelibs carry absolute library paths (`typelibi.py`), and `core/zasebni_webkit.py` puts the package's typelibs first in `GI_TYPELIB_PATH` before `import gi` — no `LD_LIBRARY_PATH`. Programs the user starts from Safeer OS (menu, dock, files, "Open with", links, scripts) get an environment without our private paths (`zasebni_webkit.okolje_za_zunanje()` / `kontekst_za_zunanje()`; also strips `$APPDIR` paths of the AppImage), so they keep the system's typelibs, GStreamer plugins and libraries. The bubblewrap sandbox stays on: Ubuntu 24.04+ restricts unprivileged user namespaces, so both packages ship AppArmor profiles for their launchers (`packaging/apparmor`, conffiles in `/etc/apparmor.d`, loaded by `postinst`) like Ubuntu's own profiles for epiphany and geary; where no profile applies, `core/peskovnik_userns.py` detects the restriction with WebKit's own bwrap probe and turns the sandbox off instead of crashing, with a one-time explanation. Release builds use PGO: job `webkit-deb-profil` builds an instrumented WebKit and records a profile with the pinned Speedometer 3.1 copy (`packaging/webkit-deb/ucni_tek.sh`, the same `pgo_trening.py` as the Flatpak), because a profile from the Flatpak build does not match a noble build (other system headers and source paths); job `webkit-deb` builds the one WebKit with it (`SAFEER_WEBKIT_PGO=uporaba`, plus BOLT) and packages `safeer-webkit` (artifact `safeer-webkit`, attached to the release). Profile and archive stay in the Actions cache keyed on these files. Without `SAFEER_WEBKIT_DEB`, `build_deb.sh` builds `safeer-browser_<version>_all.deb` on the system's WebKitGTK (local development and tests).

The source tarball `safeer-browser-linux.tar.gz` (`install.sh`) installs the GTK 4 browser (`safeer_brskalnik.py`) like the packages. `debian/` (PPA source package, Ubuntu 24.04 on) installs the same payload through `packaging/install_payload.sh`. Builds no longer copy into neighbouring website repositories. Native package upgrades continue using the existing `~/.config/safeer-mint` profile unless XDG_CONFIG_HOME is explicitly set. Existing alternatives registration and removal scripts are retained.

The `.deb` packages of the browser, Safeer Control and Safeer OS compile the Python byte-code in `postinst` (`python3 -m compileall` on the program folder): a user cannot write into `/usr/lib`, so without it Python would compile every module again at each start. `prerm` removes the byte-code again — on removal and before an upgrade — because dpkg does not know these files and would otherwise leave the program folder behind. AppImage and Flatpak ship the code read-only and are unchanged.

## Flatpak

```sh
flatpak remote-add --user --if-not-exists flathub https://flathub.org/repo/flathub.flatpakrepo
flatpak install --user flathub org.gnome.Platform//50 org.gnome.Sdk//50
# Also install your distribution's flatpak-builder and AppStream compose tools.
bash packaging/build_flatpak.sh
flatpak install --user dist/Safeer-Browser-1.0.127-x86_64.flatpak
flatpak run io.github.memelandfaner.SafeerBrowser
```

This builds the local checkout, not an unrelated old tag. For a Flathub submission, replace the local `dir` source with an immutable public release commit or source archive plus SHA256; keep the same install command. The current local-source manifest is a development/release-bundle manifest, not a completed Flathub submission.

Permissions:

The manifest builds our WebKitGTK 6.0 from `packaging/webkit/webkitgtk6-safeer.yml` and `webkitgtk6-safeer-typelib.yml`, the same files the Safeer OS manifest uses. flatpak-builder keys its cache by app ID, so CI builds and caches the browser's WebKit in its own job (`flatpak-brskalnik`).

Since 15 Oct 2026 both Flatpaks built by CI (every push and every `v*` tag, the files attached to releases) use WebKitGTK compiled with a profile (PGO, `packaging/webkit/pgo.py`; Speedometer 3.1 on the test PC: 9.2 with Clang + ThinLTO, 10.7 with PGO). The profile is keyed by `pgo.py kljuc` (WebKit module and patches, the training run, the LLVM version of the `llvm22` SDK extension) and stored as the artifact `webkit-pgo-profraw-<key>` for 90 days; the `webkit-pgo-ucenje` job (instrumented build and a Speedometer 3.1 training run, about 1.5-2.5 h) runs only when no profile with the current key exists. `flatpak` and `flatpak-brskalnik` never fall back to a build without PGO: without a valid profile they do not run, and the release job needs both. A local `bash packaging/build_flatpak.sh` builds without PGO; `SAFEER_FLATPAK_MANIFEST="$(python3 packaging/webkit/pgo.py uporaba DIR_WITH_PROFRAW)"` builds with a downloaded profile. Measured in CI (15 Oct 2026, runs 38787148915 and 38801491087): instrumented build 1 h 40 min, training run under a minute (8 `.profraw`, 124 MB, artifact 34 MB), PGO builds 1 h 26 min (Safeer OS) and 1 h 46 min (browser); flatpak-builder caches 0.7 GB (Safeer OS), 0.33 GB (browser) and 0.38 GB (instrumented), well under GitHub's 10 GB per repository. The profile file `/app/share/webkitgtk-safeer/profil.txt` lists the source paths of its local functions; CI requires them all to be `/run/build/webkitgtk6-safeer-pgo`, the build path of the PGO module (the old manual path used different module names, so local functions got no profile).

Permissions:

- Wayland and fallback X11, IPC: windows and X11 shared-memory rendering; X11 is also how Safeer DRM's window is embedded into the tab.
- DRI: graphics acceleration, no unrestricted device access.
- Network: websites, encrypted DNS, local loopback proxy and media.
- PulseAudio: sound; browser microphone requests still require the application's permission handling.
- `home`: the same settings, sign-ins, cookies and bookmarks as the .deb (`~/.config/safeer-mint`; the launcher sets `XDG_*` to the home folder like Safeer OS), downloads to the XDG Downloads folder, bookmark import from Firefox/Chrome profiles, and Safeer DRM, which runs on the host from the package (`/app` as the host sees it, `[Instance] app-path` in `/.flatpak-info`) with its sign-in profiles in `~/.local/share/safeer-drm` and session files in `~/.cache/safeer-drm`.
- `host-os:ro`, `/var/lib/flatpak:ro`, `/var/lib/snapd/desktop:ro`: the computer's program for `mailto:`, `magnet:` ... links and the Widevine fallback browser.
- `--talk-name=org.freedesktop.Flatpak`: `flatpak-spawn --host` for Safeer DRM (Chromium keeps its own sandbox on the host), opening links in host programs and the tool wrappers in `/app/host-bin`. This allows running host commands, so the Flatpak is a bundle with our WebKit, not a sandbox boundary; narrower filesystem permissions would not change that.
- `GTK_USE_PORTAL=1`: native file chooser and URI opening use desktop portals.

Setting a host default browser inside the sandbox is deliberately unsupported: choose Safeer in system settings. Camera, microphone, clipboard, portal uploads and external handlers require the desktop acceptance checks below. No camera device permission is added speculatively.

## AppImage

Release build baseline: Ubuntu 24.04 x86_64 / glibc 2.39 (GTK 4 and WebKitGTK 6.0, like the Safeer OS AppImage). CI runs the `brskalnik` job in an `ubuntu:24.04` container; locally, use the same container or an Ubuntu 24.04 machine and install the dependency set in `.github/workflows/linux-packages.yml`. The script refuses a newer build host by default. `ALLOW_NEWER_GLIBC=1` is for diagnostic builds and does not establish compatibility with older distributions.

```sh
bash packaging/fetch_linuxdeploy.sh
LINUXDEPLOY="$PWD/build/tools/linuxdeploy.AppImage" bash packaging/build_appimage.sh
chmod +x dist/Safeer-Browser-1.0.127-x86_64.AppImage
./dist/Safeer-Browser-1.0.127-x86_64.AppImage
```

linuxdeploy is pinned to a versioned release and checked against SHA256. The AppDir includes Python, GI modules/typelibs, GTK, WebKit subprocesses, GStreamer and GIO TLS resources. linuxdeploy resolves ELF dependencies and applies its system-library exclusions. glibc, the ELF loader and GPU drivers must remain host-provided. WebKit process sandboxing is not disabled. Host bubblewrap/user-namespace support may be required by the distro WebKit build. A build must fail acceptance rather than use an insecure fallback.

AppImages do not automatically register a permanent desktop launcher. Use desktop integration before selecting the app as a default browser. Files in the transient AppImage mount must not be registered as permanent executables.

## Safeer OS for Linux (safeer-os)

Safeer OS is the Safeer desktop on top of Linux Mint: a workspace (search, programs, files, media, devices, Shield, Splet) with the dock below; it talks to Safeer Control over D-Bus and runs it in its own process. Since 12 Oct 2026 the .deb is **one package**: `safeer-os` carries Safeer OS (`packaging/install_os_payload.sh`), Safeer Control with `safeerctl` (`packaging/install_control_payload.sh`) and Safeer Cinnamon (`packaging/install_cinnamon_payload.sh`), so a double click in GDebi installs everything and one update keeps it current. It `Provides` and `Replaces` the former `safeer-control` and `safeer-cinnamon` packages without `Conflicts`, so an update takes their files over and they disappear without their `prerm remove` (which would turn the user's Safeer Cinnamon look off); `tools/mint_namestitev` checks this on Linux Mint against the last release. Versions: `packaging/VERSION_OS`, `VERSION_CONTROL`, `VERSION_CINNAMON`.

```sh
bash build_os_deb.sh
SAFEER_WEBKIT_DEB=safeer-webkit_1.0.127_amd64.deb bash build_os_deb.sh   # on our WebKitGTK: Depends safeer-webkit (>= 1.0.127)
sudo apt install ./safeer-webkit_1.0.127_amd64.deb ./safeer-os_0.4.85_amd64.deb    # nothing on the desktop changes until "Safeer Cinnamon" is opened in the menu
LINUXDEPLOY="$PWD/build/tools/linuxdeploy.AppImage" bash packaging/build_os_appimage.sh   # Safeer-OS-<version>-x86_64.AppImage (Safeer OS + Control; `--control` starts Control)
bash packaging/build_os_flatpak.sh                                                        # Safeer-OS-<version>-x86_64.flatpak (io.github.memelandfaner.SafeerOS)
```

Since 18 Oct 2026 the package also carries **Node.js 22 LTS** ("deb" mode): `packaging/node_vendor.py` downloads the pinned `node-v22.x-linux-x64.tar.xz`, checks its pinned SHA-256 and installs only `bin/node` (stripped) into `/usr/lib/safeer-os/node`, never into `PATH` — a system `node` stays untouched; the licence goes to `/usr/share/doc/safeer-os/nodejs/LICENSE`. Programs find it through `core/node_izvajalnik.py`. `SAFEER_DEB_BREZ_NODE=1` builds a package without it (tests). A new version runs right after installation: Safeer OS and Safeer Control watch their installed version file (`core/nova_razlicica.py`) and, when nothing is playing, calling or transferring and the user is away (or asked for the update in Safeer OS), save open Splet tabs and playback, exit normally and are started again by their launcher (exit code 75). Job `qt-xcb` installs the package in a clean `ubuntu:24.04` container without recommended packages and checks with `packaging/preveri_qxcb.sh` that PySide6's xcb plugin finds every library; the Mint test does the same on Linux Mint 22 and 22.3.

The Flatpak needs more than the browser: the session bus (Safeer Control's D-Bus name), the home folder (Files), PipeWire/PulseAudio and `--talk-name=org.freedesktop.Flatpak`, because Safeer OS controls the computer with the system's own tools (`nmcli`, `pactl`, `resolvectl`, `pkexec`, `gsettings`, `systemctl` ...). Inside the sandbox these are wrappers in `/app/host-bin` (`packaging/flatpak_host_wrappers.sh`) that run the host's tool through `flatpak-spawn --host`. The Flatpak is therefore a bundle for people who prefer Flatpak, not a sandboxed build; the .deb is the primary format on Linux Mint. Flathub is not a target: since May 2026 Flathub rejects applications developed with generative AI, which Safeer openly is; the bundles are published on GitHub and safeer.si instead.

## Editing shared files from devices (Safeer Control 2.1.0+)

Devices (Safeer OS on the TV and tablet) may rename, move and delete the files Control shares and rotate pictures: `POST /d/<id>` on the same pinned-TLS file server, with the same per-device token as downloads, body `{"op": "delete"|"rename"|"move"|"rotate", ...}` (`core/link_urejanje.py`, `tests/test_link_urejanje.py`). Delete moves to the freedesktop Trash (`gio trash`, fallback `~/.local/share/Trash`); rename/move never overwrite and stay inside the shared folders; the shared roots themselves are protected. A JPEG with an EXIF orientation tag is rotated by rewriting only that tag (lossless); other images need Pillow (`python3-pil`, recommended by the .deb; bundled in the Flatpak as a wheel).

## Safeer DRM (Widevine) in the packages

Since 1.0.127 (owner's decision, 18 Oct 2026) Safeer DRM is part of every package like everything else and is no longer downloaded while Safeer runs. `packaging/safeer-drm.json` pins castLabs ECS (Safeer DRM 0.2.0 = ECS 44.5.1+wvcus: SHA-256 of the zip and of the `safeer-drm` program). `python3 packaging/safeer_drm_paket.py pripravi build/safeer-drm` downloads and verifies it and prepares the folder; with `SAFEER_DRM_TOVOR=build/safeer-drm` the payload scripts install it read-only as `<payload>/safeer-drm` (`/usr/lib/safeer-os/safeer-drm`, `/usr/lib/safeer-browser/safeer-drm`, `/app/lib/...`; in the AppImages `opt/safeer-drm`, out of linuxdeploy's reach) with the licence notices in `share/doc/<package>/safeer-drm/`. The .deb packages add the system libraries ECS needs to Depends (`deb_odvisnosti`). The Flatpak manifests list the zip as a flatpak-builder source with the same URL and SHA-256 (a test compares them). Without `SAFEER_DRM_TOVOR` (source builds, tests, `debian/`) a package has no Safeer DRM; release CI checks that every package has it.

The Google Widevine CDM is deliberately **not** in the packages (owner's decision after the castLabs FAQ: a bundled CDM raises decoder-licensing questions, while a CDM that ECS downloads from Google's servers is covered by Google's licence). On the first protected content `assets/safeer_drm/main.js` waits for `components.whenReady()`: ECS downloads the CDM from Google's component update service into the user's `WidevineCdm` folder (`$XDG_CONFIG_HOME/Safeer DRM/WidevineCdm`, in the browser Flatpak `~/.var/app/<ID>/config/...`) and keeps it updated - the user installs nothing and sees no button. Measured on 18 Oct 2026 (ECS 44.5.1, Chromium sandbox, fresh profile): CDM 4.10.3112.0 installed and EME working in the same first start, about 2 s. Electron's spell-check dictionary download stays off. The copy of Safeer DRM that earlier versions downloaded into `~/.local/share/safeer-drm/<version>` is removed on start (`core/safeer_drm.pospravi_staro`); sign-in profiles and the downloaded CDM stay.

## Our rqbit (torrent engine) in the packages

Magnet links in Safeer OS and Safeer Control run on [rqbit](https://github.com/ikatson/rqbit) (Apache-2.0, `core/os_torrent.py`). The official rqbit 9.0.1 does not start on a Linux kernel without IPv6 (`ipv6.disable=1`, some containers): the TCP listener, DHT, LSD and the UDP tracker client bind `[::]` and get `EAFNOSUPPORT`, the UDP tracker client even with `--ipv4-only` (measured 18 Oct 2026). Owner's rule: we fix bugs in open-source software, ship our fix right away and propose it upstream. `packaging/rqbit/ipv4-fallback-without-ipv6.patch` makes rqbit use IPv4 only when the OS has no IPv6 and changes nothing when it has; the upstream proposal (issue and PR text) is in `docs/upstream/rqbit-ipv4-fallback.md`.

`packaging/rqbit/rqbit.json` pins the source (tag, commit and SHA-256 of the source tree), the patch (SHA-256), Rust and the target. `python3 packaging/rqbit/rqbit_paket.py zgradi build/rqbit` clones and checks the source, applies the patch and builds a static program (`x86_64-unknown-linux-musl`, `--no-default-features --features rust-tls`, `cargo --locked`) with `LICENSE`, `OBVESTILO.txt`, `LICENSES-THIRD-PARTY.txt` (licences of every library in the program) and a build record `gradnja.json`. CI job `rqbit-deb` builds it only when something in `packaging/rqbit/` changes (cache key) and on every run checks the record and downloads a torrent through a local UDP tracker with `socket(AF_INET6)` blocked by seccomp (`rqbit_paket.py dim --brez-ipv6`). Before installing, `rqbit_paket.py namesti` checks that the record matches the pins, the program's SHA-256, that it is static and its version.

Where it goes and how Safeer finds it (`core/os_torrent.vgrajen_program`):

- .deb (`SAFEER_RQBIT_TOVOR`, `build_os_deb.sh`): `/usr/lib/safeer-os/rqbit/rqbit`, notices in `/usr/share/doc/safeer-os/rqbit/`. Safeer Control (`/usr/lib/safeer-control`) uses the same program.
- Flatpak Safeer OS (source `build/rqbit` in the manifest, `packaging/build_os_flatpak.sh` refuses to build without it): `/app/lib/safeer-os/rqbit/rqbit`.
- AppImage Safeer OS (`SAFEER_RQBIT_TOVOR`, required in CI): `opt/rqbit/rqbit`, out of linuxdeploy's reach; `AppRun-os` passes it in `SAFEER_RQBIT`.
- Windows keeps downloading the official release (`RQBIT_PAKETI`, SHA-256 pinned in `core/os_torrent.py`) on first use: our fallback in rqbit only applies on Unix (`cfg(unix)`), and the patch is not tested on Windows. Safeer Browser has no magnet support and carries no rqbit.

Any other Linux build without the bundled program (for example a source checkout) also downloads the official release, as before.

## Tests and release gates

```sh
python3 packaging/check_version.py
/usr/bin/python3 -m unittest discover -s tests -p 'test_*.py'
xvfb-run -a dbus-run-session -- /usr/bin/python3 packaging/smoke_brskalnik.py build/stage/usr/lib/safeer-browser
```

The smoke test uses temporary settings, opens the actual Safeer window and checks WebKit renders local HTML, a download writes the exact bytes, settings persist, in the Flatpak that WebKitGTK is loaded from `/app`, and that Safeer DRM is started the way the browser starts it (through zypak inside the browser Flatpak) and embedded into the browser window on X11 - with a stand-in helper instead of the real Safeer DRM, which `packaging/smoke_drm_peskovnik.py` runs with Widevine inside the browser Flatpak. `packaging/smoke.py` is the GTK 3 browser's smoke test. It requires a graphical display. It does not use a real browsing profile. Use `xvfb-run -a` on CI where supported.

The workflow builds all formats, uploads artifacts and makes **draft** tagged releases. A published release is final: the workflow never replaces its files (builds are not bit-for-bit reproducible, and the checksums of the tested files are in the update manifest on safeer.si), and publishing a release does not start a build. Complete these acceptance checks before publishing:

- .deb installation, upgrade, start and removal are tested by the workflow itself: the `mint` job (`tools/mint_namestitev`) installs the last published release on Linux Mint 22 and 22.3, upgrades it to the very files of the new release with the command Safeer OS itself uses, starts Safeer OS as a normal user and checks that nothing is left after removal; the release job requires it. Still by hand: the desktop itself (the Cinnamon look, the panel, the workspace).
- Test installed Flatpak, not only `flatpak build`: nested runtime sandboxes require an installed app.
- Verify launcher name/icon, network HTTPS, download and portal-selected save/upload, clipboard, external URI confirmation, sound, microphone and camera behavior on X11 and Wayland.
- Close and reopen: cookies/settings survive; no cross-format profile corruption.
- Verify AppImage extracted launch and FUSE launch on Ubuntu 24.04, Mint 22 and an independent current distribution; confirm process sandbox active.
- Inspect AppImage licenses, runtime resource paths and host-library exclusions.
- Flatpak: run Flathub manifest/AppStream lint, verify screenshot links, confirm app-ID ownership and pin release sources.

The current application does not implement a separate incognito profile; the shared desktop file therefore does not advertise a nonfunctional private-window action. Packaging does not invent that security feature.
