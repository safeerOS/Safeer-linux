# Safeer Browser for Linux 1.0.90 · Safeer Control 2.1.46 · Safeer OS 0.4.48

## Safeer Control 2.1.46

- **"Rename device" works when the computer is the hub.** The hub on a computer had no way to take a name the user gives a device (`/cast/devices/rename` answered 404), and Safeer Control asked for a pairing token, which a computer that is its own hub does not have. Renaming a device from the computer therefore always failed. The name now goes into the trust ring, as on the Android hub, so every device in Safeer Link sees it. An empty name gives the device back the name it reports about itself.
- **`safeerctl` – Safeer Link from the command line.** `safeerctl devices`, `capabilities`, `info` (processor, memory, storage, battery – what the device reports about itself), `apps`, `run APP --on DEVICE`, `send FILE --to DEVICE`, `text`, `rename`. A device is named by its id or by a part of its name. Every command takes `--json` for scripts and agents, and the exit code says what happened. `safeerctl` talks to the Safeer Control that is running and holds no keys of its own; it also works from an SSH session or cron. In the AppImage it is `--ctl`, in the Flatpak `--command=safeerctl`. See [docs/SAFEERCTL.md](docs/SAFEERCTL.md).
- **One list of capability names.** What a device announces when it joins Safeer Link (`file`, `text`, `apps`, `remote` …) is now described in one place, `core/link_zmoznosti.py`, and a test fails when the code announces a capability that is not in the list.

## Safeer OS 0.4.48

- **When a device cannot be renamed, Safeer OS says why** – an older Safeer Control is running, this computer is not in Safeer Link, the hub cannot do it yet – instead of only "The name could not be saved."

Not yet: renaming through a hub on a computer that still runs an older Safeer Control (Safeer OS now says so). `safeerctl send` has the limits of sending from Files: no folders, and the device has to be at home.

Safeer Browser 1.0.90 has no changes of its own (same code, new number).

Slovensko: **Safeer Control 2.1.46 – »Preimenuj napravo« deluje tudi, ko je središče računalnik.** Središče na računalniku ni imelo poti, po kateri uporabnik napravi da ime (`/cast/devices/rename` je odgovoril 404), Safeer Control pa je zahteval žeton seznanitve, ki ga računalnik kot lastno središče nima. Preimenovanje naprave z računalnika zato ni nikoli uspelo. Ime gre zdaj v krog zaupanja, kot na središču na Androidu, zato ga vidijo vse naprave v Safeer Linku. Prazno ime napravi vrne ime, ki ga pove sama o sebi. **`safeerctl` – Safeer Link iz ukazne vrstice.** `safeerctl devices`, `capabilities`, `info` (procesor, pomnilnik, prostor, baterija – kar naprava pove o sebi), `apps`, `run PROGRAM --on NAPRAVA`, `send DATOTEKA --to NAPRAVA`, `text`, `rename`. Napravo poveš z id-jem ali delom imena. Vsak ukaz pozna `--json` za skripte in agente, izhodna koda pove, kaj se je zgodilo. `safeerctl` govori s Safeer Controlom, ki teče, in nima svojih ključev; dela tudi iz SSH-seje ali crona. V AppImage je to `--ctl`, v Flatpaku `--command=safeerctl`. **En seznam imen zmožnosti.** Kar naprava oglasi ob prijavi v Safeer Link (`file`, `text`, `apps`, `remote` …), je zdaj opisano na enem mestu, `core/link_zmoznosti.py`; test pade, če koda oglasi zmožnost, ki je v seznamu ni. **Safeer OS 0.4.48 – ko naprave ni mogoče preimenovati, Safeer OS pove zakaj** (teče starejši Safeer Control, računalnik ni v Safeer Linku, središče tega še ne zna) namesto samo »Imena ni bilo mogoče shraniti.« Še ne gre: preimenovanje prek središča na računalniku, kjer še teče starejši Safeer Control (Safeer OS to zdaj pove). `safeerctl send` ima omejitve pošiljanja iz Datotek: brez map, naprava mora biti doma. Safeer Browser 1.0.90 nima svojih sprememb.
